# Графическая оболочка

Игра собирается в двух видах из одной и той же логики:

| | `make` | `make gui` |
|---|---|---|
| Бинарник | `andors-love` | `andors-love-gui`, а для Android `make gui-so` даёт `libandors-love-gui.so` |
| Вывод | терминал, ANSI | SDL2, окно или весь экран |
| Ввод | клавиатура | касания **и** клавиатура |
| Зависимости | нет | SDL2 |

Логика (`src/content`, `src/world`, `src/game`, `src/save`) обеими оболочками
не тронута: `src/ui.cpp` — терминальная оболочка, `src/gfx/` — графическая.
Тесты гоняют логику одну и ту же, поэтому переход на графику ничего в мире
не сдвинул: все прежние проверки, включая сквозное прохождение всех
пятидесяти четырёх квестов, проходят как проходили.

## Управление касанием

| Жест | Что делает |
|---|---|
| **Тап по полю** | герой идёт к точке, пока не упрётся или пока не тапнут ещё раз |
| **Удержание** | бег: герой ускоряется и идёт за пальцем, пока палец на экране |
| **Свайп** | шаг в сторону свайпа; длинный свайп даёт несколько шагов подряд |
| **Тап по себе или в стену**, когда герой стоит | внутриигровое меню |
| **Тап по идущему герою** | остановиться |
| **Тап по пункту** | выбор (одним касанием, без подтверждения) |
| **Тап мимо окна** | закрыть окно |

Поиска пути нет намеренно, и обещание игроку ровно такое, какое выполняется:
герой идёт **в сторону** точки — сперва по оси с большей разницей, потом по
второй. Этого хватает, чтобы обойти угол; в тупик он не пойдёт, а упрётся
и остановится. Ходьба доводит начатое до конца: упёршись в жителя, она
заводит разговор, а не молча замирает.

Клавиатура работает как раньше: `WASD`/стрелки, `C I Q K F P B`, `M` —
меню, `1 2 3` — стойка. Escape поддержан, но нигде не обязателен: на
экранной клавиатуре Android его набирают сочетанием, и требовать его нельзя.

## Интерфейсы

Все экраны, кроме главного меню, — полупрозрачные окна поверх мира. Мир
под ними продолжает быть виден, и видно, где стоит герой. Затемнение
кладётся перед каждым окном стопки, иначе два окна подряд просвечивают
друг сквозь друга.

Окно ужимается под содержимое: меню из трёх пунктов не занимает пол-экрана.
Строка списка ростом с палец (не меньше `touch_unit`), потому что промах в
списке раздражает сильнее, чем лишняя прокрутка.

**Главное меню** — единственный экран без наложений. На нём только прогресс
выбранного героя (имя, уровень, раса и ремесло, где стоит, сколько заданий
пройдено и сколько в работе, золото, ход) и пункты выбора.

## Почему не ImGui

Готовая библиотека сюда не легла по двум причинам, и обе существенные:

1. **Шрифт.** Игра целиком на русском. Встроенный атлас ImGui кириллицы не
   содержит, а подключать TTF и таскать его в APK — ровно та работа, от
   которой библиотека должна была избавить.
2. **Касание.** У ImGui касание — это эмуляция мыши. Здесь тап, удержание и
   свайп — три разные команды с разным смыслом, и различает их отдельный
   распознаватель (`src/gfx/touch.*`), который надо было бы писать всё равно.

Виджетов нужно немного, и они уместились в один файл (`src/gfx/gui.cpp`,
около 250 строк): панель, кнопка, список с прокруткой, абзац с переносом.
Зато размеры считаются от размера пальца, а не от размера курсора.

## Шрифт

Растровый, моноширинный, 8×16, 179 глифов: латиница, кириллица с Ё и та
пунктуация, что встречается в текстах. Лежит в `src/gfx/font_data.cpp`
как массив битов и генерируется из DejaVu Sans Mono:

```bash
make font        # нужен python3-pil; трогать только при правке набора символов
```

Моноширинность здесь не украшение: весь текстовый слой игры (`wrap`, `pad`,
`trunc`) считает символы, а не пиксели, и на этом держится вся вёрстка.
Тест проверяет, что **каждый** символ, который игра умеет напечатать —
в записках, диалогах, названиях, эпилогах и на табличках карт — в шрифте
есть. Дыру в тексте должен находить тест, а не игрок.

## Исполняемый файл или библиотека

`make gui` собирает обычный исполняемый файл — для настольной машины и для
Termux с X-сервером. На Android SDL2-приложение устроено иначе: это
**разделяемая библиотека**, которую загружает активность SDL и вызывает в ней
`SDL_main` (в обычной SDL2-сборке под Android результат так и называется —
`libmain.so`). Для этого есть `make gui-so`.

Никакого отдельного кода это не требует: `<SDL2/SDL.h>` в файле с `main()`
на Android сам делает `#define main SDL_main` и объявляет `SDL_main` с сишной
компоновкой и видимостью `default`. Цель `gui-so` только собирает с `-fPIC`,
линкует с `-shared` и убирает `-pie`, который с `-shared` несовместим.

## Какой SDL2 нужен

**2.0.0.** Ничего новее код не использует: в C4Droid лежит SDL2 старее
2.0.5, и удобная `SDL_CreateRGBSurfaceWithFormat` там просто не
компилируется. Поверхности создаются через `SDL_CreateRGBSurface` с явными
масками (`new_surface32` в `draw.cpp`). Проверить, что запрет соблюдён,
можно компиляцией с подменёнными именами:

```bash
g++ -std=c++11 -fsyntax-only $(sdl2-config --cflags) \
    -DSDL_CreateRGBSurfaceWithFormat=POISON -DSDL_PIXELFORMAT_RGBA32=POISON \
    src/gfx/*.cpp 2>&1 | grep '^src/gfx/.*error'
```

Пусто — значит, ничего новее 2.0.4 не задето.

## Как это проверяется без экрана

Логику ввода можно проверить тестами: разбор UTF-8 и покрытие шрифта,
распознавание жестов (тап, порог свайпа, удержание, два пальца), ходьба
по тапу (доходит, упирается, бежит быстрее, разговор её прерывает, а
подобранная с земли трава — нет). Это входит в `make test`.

Рисование так не проверить, поэтому у графической сборки есть прогон
по сценарию:

```bash
SDL_VIDEODRIVER=dummy ./andors-love-gui --script сценарий.txt каталог
```

Команды сценария: `tap X Y`, `hold X Y`, `release`, `swipe DX DY`,
`key K`, `wait MS`, `shot ИМЯ`, `quit`. События идут через тот же
распознаватель, что и живой палец, а `shot` сохраняет кадр в BMP.
Так снимки экрана получаются на сборочной машине, где нет ни дисплея,
ни пальцев.
